# DOD — solidexplorer-license

Evidence for every claim in `README.md`. Each line is a command that was run and
its observed result, not a restatement of intent.

## Definition of done, from PLAN.md

| # | requirement | evidence |
| --- | --- | --- |
| 1 | the scheme is read, not guessed | every parameter traced to a class and quoted in `RESEARCH.md`; `keys` prints them |

## The constant that was wrong

The salt was first written as `...4d8ddc...` from a decompiler listing. The
bytecode has `...4d8bdc...`. Found by searching `classes4.dex` for the byte run:

```
$ python3 -c "... d.find(bytes([0xd2,0x41,...])) ..."
10 byte pertama SALT: di offset 887020
konteks: 0003010014000000d2411e8099c74ac03358a1d34d8bdc8ff520c0590500020003000000
                                                   ^^ 8b
```

And the check was shown to fail when the wrong byte is restored:

```
$ (salt set back to 0x8d)
--- FAIL: TestConstantsMatchTheAPKBytecode
    apk_test.go:44: salt d2411e8099c74ac03358a1d34d8ddc8ff520c059 does not appear in classes4.dex
exit 1
```

This is why the golden vectors are documented as not validating the constants:
they were generated by the same code that held the wrong salt.

## Mutation results

23 mutations, applied one at a time to the source, each required to fail the
suite. All 23 were caught.

```
salt 0x8b -> 0x8d                        caught
IV 0xb0 -> 0xb1                          caught
PBKDF2Iterations 1024 -> 1               caught
KeyBits 256 -> 128                       caught
HeaderPrefix changed to ...-2|           caught
pad bytes not checked                    caught
pad length not validated                 caught
header check skipped                     caught
password = package only                  caught
PBKDF2 derived one block only            caught
no unpadding                             caught
PKCS#5 pad byte always 1                 caught
PBKDF2 XOR accumulation step skipped     caught
EncryptRaw does not require whole blocks caught
device mismatch stops clearing            caught
empty id treated as a match              caught
TRIAL reported as LICENSED               caught
status not normalised                    caught
future trial start -> expired            caught
TrialLength 14d -> 7d                    caught
decryption error read as present         caught
Clear does not clear                     caught
IsLicensed: trial passes as paid         caught
```

Two mutations that initially escaped, and what was added for each:

- *pad bytes not checked* — the first test built a malformed pad and then ran it
  through `encrypt`, which appended another block of padding and pushed the
  corrupted byte into the payload where nothing validates it. The test passed
  against a reader that ignored pad bytes entirely. Fixed by encrypting the
  padded block directly (`EncryptRaw`), which is now a real code path with its own
  test.
- *empty id treated as a match* — the test covered an absent id, which is a
  different branch from a present-but-empty one. A second test was added for the
  empty case.

The APK itself is not committed. `apk_test.go` reads `testdata/soldi.apk` when
present and skips when it is absent, so the suite is runnable from a clone
without the artifact — and `run.sh` says which path it took rather than reporting
a green suite that quietly checked less.

## What was not done

- Google Play Billing was not touched. The purchase path is Google's.
- The app was not executed, so no claim is made about how it responds to a
  modified store.
- One build was examined (6.0.1). Constants in other builds were not compared.
- `sale_active` and `special_offer` are read and written but not interpreted.
